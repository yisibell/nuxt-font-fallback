# 关于字体加载导致的布局偏移：问题与解决方案

[English](./how-it-works.md)

## 问题：字体切换为什么会造成页面跳动

打开网页时，品牌字体通常需要从网络下载。在下载完成前，浏览器会先用设备上已有的字体显示文字。这种临时使用的字体就是**备用字体**。

不同字体即使字号相同，文字宽度和行高也可能不同。例如一排商品标签使用备用字体时排成三行，品牌字体加载后变成两行，下面的内容就会随之上移。这种可见的页面位置变化会影响用户体验，也可能计入 **CLS（累积布局偏移）**。

## 标签布局为什么容易出现明显的 CLS

商品分类、筛选条件等标签通常按顺序横向排列，空间不够时自动换到下一行。**换行是一个临界变化**：一行只要多出几像素，就可能把整个标签挤到下一行；后面的标签也可能跟着重新排列。如果总行数变化，标签区域下方的内容也会随之移动。

例如，某一行宽度为 `600px`：品牌字体下标签刚好占 `598px`，而备用字体下占 `605px`。虽然只差 `7px`，备用字体下最后一个标签仍会被挤到下一行。品牌字体加载后，标签重新排回上一行，下面的内容随之上移，造成明显的布局偏移。实际 **CLS** 取决于受影响元素的可见面积和移动距离，因此不能只用字体宽度误差推算具体 **CLS** 数值。

## 解决方案：调整备用字体

模块在网站构建阶段计算备用字体的调整参数，让浏览器在品牌字体加载期间使用经过调整的备用字体，尽量让切换前后的文字宽度和行高接近。用户无需为每段文字分别计算；目标字体本身仍由应用负责加载。

它能降低布局变化的风险，但不能保证所有文字宽度一致或 **CLS** 一定为零。应结合实际页面内容、设备和字体验证。

**在标签布局中使用的步骤：**

1. 配置目标字体文件和设备上可能存在的备用字体，让模块生成经过度量调整的 fallback。
2. 在标签样式的 `font-family` 中，将目标字体放在前面、生成的备用字体族放在后面。目标字体尚未加载时，浏览器就会使用调整后的备用字体。
3. 如果普通 fallback 对标签仍有明显宽度误差，可以开启 **Balanced**，并配置一个或多个 `balancedWidthWeight`，选择对实际标签更合适的版本。不同场景可以引用不同的生成字体族，无需为每个标签单独计算。
4. 在真实标签文本、常见屏幕宽度和目标设备上，分别检查字体加载前后的行数、标签位置与页面下方内容的位移，再通过性能工具测量实际 CLS。

例如，配置 `balancedWidthWeight: [0.27, 0.9]` 后，可以在标签样式中选择第一组：

```css
.tag {
  font-family: 'Gotham', 'GothamOverrideBalanced1', sans-serif;
  white-space: nowrap;
}
```

这里的 `white-space: nowrap` 让单个标签内部的文字不拆行；标签之间仍可正常换行。`0.27` 只是一个示例：它可能适合某组全大写标签，却让其他正文变窄。模块只能尽量缩小差异，不能保证任意文本都不跨过换行临界点。必要时，还可以为标签区域预留合适空间，减少行数变化对后续内容的影响。

## 使用标签 Demo 验证效果

项目 [Playground 首页](https://nuxt-font-fallback.vercel.app/)的 **Uppercase text preview** 可作为测试样例：同一组商品分类标签分别以普通大小写和全大写展示，并随容器宽度自动换行。这两组文字能帮助观察同一套备用字体对不同文本的影响。

建议在同一浏览器、屏幕宽度、设备和网络条件下，分别测试未使用模块调整的备用字体、模块生成的备用字体，以及目标字体加载后的状态：

1. 使用开发者工具限制网络速度并禁用缓存，刷新页面，观察目标字体加载前后的标签行数和位置。
2. 分别开启和关闭页面的 **Metric Override**，比较字体切换时标签是否重新换行，以及标签区域下方的内容是否移动。
3. 调整几种常见的视口宽度，尤其关注标签接近换行的位置；普通大小写和全大写两组都要检查。
4. 使用浏览器性能工具记录实际 **CLS**，并注明测试设备、视口宽度、网络条件、字体及模块配置。重复测试后再比较结果。

**正常文本**

| 屏幕宽度（视口） | 记录项 | 未调整备用字体 | 模块生成的备用字体 |
|---|---|---|---|
| `870px` | 字体切换前后标签行数 | `3行变4行` | `不变` |
| `870px` | 标签位置及下方内容是否发生位移 | `是` | `否` |
| `870px` | 页面实际 **CLS** | `0.38` | `0.00` |

**大写文本**

| 屏幕宽度（视口） | 记录项 | 未调整备用字体 | 模块生成的备用字体 |
|---|---|---|---|
| `715px` | 字体切换前后标签行数 | `不变` | `不变` |
| `715px` | 标签位置及下方内容是否发生位移 | `是` | `否` |
| `715px` | 页面实际 **CLS** | `0.24` | `0.00` |

**CLS** 是整个页面的指标。表中记录的是对应测试场景的页面 **CLS**，不代表数值全部由该组文本造成；应通过性能工具检查具体偏移来源。

首页的 **Metric Override** 开关同时控制普通 fallback 和标签 Demo 使用的 **Balanced** fallback；关闭时，标签在目标字体不可用期间使用浏览器的 `sans-serif` 备用字体。Base 标签使用 `Balanced2`，全大写标签使用 `Balanced1`；开关不会切换这两组权重。首页还会显示其他内容，因此页面级 **CLS** 可能包含其他元素的位移；应结合性能工具中的具体布局偏移记录判断原因。表中结果对应已测场景，其他测试条件下可能有所不同。

## 模块实现原理：字体度量描述符

模块生成四项 CSS 设置来调整备用字体。可以把它们理解为：一项调整文字大小，另外三项调整浏览器为文字上下和行与行之间安排的空间。

| 描述符 | 作用 |
|---|---|
| `size-adjust` | 整体放大或缩小备用字体。文字宽度也会随之变化，从而影响一行能放多少文字。 |
| `ascent-override` | 调整文字基线以上的排版空间。基线可以理解为大多数字母底部对齐的参考线。 |
| `descent-override` | 调整基线以下的排版空间，例如字母 `g`、`p` 向下伸出的部分所需空间。 |
| `line-gap-override` | 调整字体提供的额外行间距度量，帮助多行文字的间距更接近目标字体。 |

后三项调整的是字体度量，并不会缩放或裁剪字形轮廓。它们对行布局的实际影响还取决于元素的 `line-height` 和同一行中的其他字体。垂直覆盖值的百分比以调整后的 em 大小为基准，因此改变 `size-adjust` 后，如果仍要匹配同一组目标度量，也需要重新计算这些覆盖值。

## 从配置到 CSS

1. 每个 `fonts` 条目指定 **web font** 文件（路径相对于 Nuxt 的 `srcDir`）和生成的备用字体族名称。web font 本身仍需由应用单独定义和加载。
2. [**Fontaine**](https://github.com/unjs/fontaine) 读取 web font 度量，并为每个 `fallbackFonts` 字体族查询 [**Capsize**](https://github.com/seek-oss/capsize) 提供的本地字体度量。
3. 模块为每个有可用度量的备用字体分别生成 `@font-face`，使用各自的 `local(...)` 来源和覆盖值。规则按配置的逆序输出，使多个本地字体均可用时，配置靠前的字体具有优先级。
4. Nuxt 将 CSS 模板写入构建目录并注入全局 CSS。应用需要在 `font-family` 中把所需的生成字体族显式放在 web font 之后。

## 普通 fallback

普通模式主要按两种字体的**平均字宽**计算缩放比例，目标是让文字整体宽度接近。它是默认开启的方案，但平均值不能保证每个单词都同样宽。

以下公式供技术人员参考；双方都有可用平均字宽时，**Fontaine** 使用的比例为：

```text
widthScale = (目标字体.xWidthAvg / 目标字体.unitsPerEm)
           / (备用字体.xWidthAvg / 备用字体.unitsPerEm)
```

`size-adjust` 缩放本地字体的字形和度量；**Fontaine** 还根据目标字体的垂直度量和缩放比例计算 `ascent-override`、`descent-override` 和 `line-gap-override`。这些描述符影响字体度量和行布局，不会把备用字体的单个字形变成目标字体的字形。

`normalFallback` 控制普通模式，默认开启。例如配置名称为 `GothamOverride` 时，默认在 `nuxt-font-fallback.css` 中生成同名字体族。

## Balanced fallback

Balanced 是可选的另一种方案，同时考虑文字宽度和视觉高度。这里的 **x-height** 可以理解为小写字母主体的高度，例如字母 `x` 的高度。它适合用来观察备用字体的视觉大小是否接近目标字体。

这两项指标有时会互相牵制：宽度更接近时，文字可能看起来偏大；视觉大小更接近时，某些文字可能更窄。Balanced 用权重在两者之间取舍，而不是保证所有场景都更好。

技术上，开启 `balancedFallback` 后，模块通过 Capsize 额外读取目标字体的完整度量，并在 Capsize 集合中查询备用字体的 **x-height**，然后组合归一化后的比例：

```text
heightScale = (目标字体.xHeight / 目标字体.unitsPerEm)
            / (备用字体.xHeight / 备用字体.unitsPerEm)
scale = widthScale * weight + heightScale * (1 - weight)
```

`balancedWidthWeight` 的范围为 0～1，默认 `0.82`。数值越大越偏向**平均字宽**，越小越偏向 **x-height**。选定的比例交给 **Fontaine** 生成规则，并计算对应的垂直覆盖值。权重为 `1` 时，比例通常与普通模式一致，但 **Balanced** 仍要求有可用的 **x-height** 数据。

单个权重生成不带编号的字体族（如 `GothamOverrideBalanced`）和 `nuxt-font-fallback.balanced.css`。数组如 `[0.27, 0.9]` 按顺序生成编号字体族（`GothamOverrideBalanced1`、`GothamOverrideBalanced2`）和文件（`nuxt-font-fallback.balanced-1.css`、`nuxt-font-fallback.balanced-2.css`）。设置 `normalFallback: false` 可以只生成 Balanced 规则；空权重数组不会生成 Balanced 文件。

## 缺失数据与实际限制

备用字体度量不可用时，生成 CSS 中会出现 `SKIP` 注释；**Balanced** 还需要可用的 **x-height** 和**平均字宽**数据。目标字体无法读取时，该条目会输出 `FAIL` 注释。如果用户设备上没有任何生成规则对应的本地字体，浏览器会继续尝试应用字体栈中的下一个字体族。

平均字宽是字体级估计，不能代表每个字符串。全大写标签、正文和不同语言的误差可能不同，在换行临界点附近，细小的宽度差异也可能改变行数。应使用实际内容和设备验证；针对某组字体或文本调出的权重不一定适用于其他情况。显式设置的 `line-height` 也会影响最终行框。
